# Obsidian Web Clipper Templates — English Version

Five Obsidian Web Clipper templates that turn a web page into a readable note:
**YouTube (desktop)**, **YouTube (iOS)**, **Default** for any page, **X (Twitter) Post** and
**Reddit Post**. Every prompt, every heading and every property in this package is in English.
Nothing is in another language, so a note reads the same as the page it came from.

> [!important] Two things must be set up before any template works
> **1. Interpreter must be on.** Every AI section — summary, key points, statement analysis —
> is generated by a model. Without Interpreter those sections stay empty and the templates
> look broken.
> **2. Use the model `glm-5.3-flash`.** These templates were built and verified against it.
> Other models were tested and produced quieter, worse output: summaries taken from comments
> instead of the description, invented steps, ignored formatting rules, wrong timestamps.
> Read [Read this first](#read-this-first-interpreter-is-required) before you import anything.

> [!note] The desktop template also expects three community plugins
> **Media Extended**, **Media Notes** and **YTranscript**. This is only so the clipped note
> works completely inside your own Obsidian — the markdown is plain and portable, but the
> video player, the media controls and the transcript need those plugins. See
> [Plugins](#plugins).

**The YouTube templates are two on purpose, and you need both if you clip on both devices.**
The desktop version uses the full site and community plugins. The iOS version cannot, because
Web Clipper on iOS only runs as a Safari extension — so it gets the mobile site, and a
reduced note. That is a limit of the platform, not of the template.

Free to use. If it saves you time, you can [buy me a coffee](#support) — optional,
never required.

## The five templates

| File | What it clips | Trigger |
|---|---|---|
| `youtube-desktop-clipper.json` | YouTube on desktop — video, summary, timestamped key points, description, folded transcript | `https://www.youtube.com/watch` |
| `youtube-ios-clipper.json` | YouTube on iPhone — video, summary | `https://m.youtube.com/watch`, `/shorts/`, `/live/` |
| `default-clipper.json` | Any other page — summary, key points, key terms, full content | *(empty — fallback for every unmatched page)* |
| `x-(twitter)-post-clipper.json` | An X / Twitter post — embedded post, key points, statement analysis | `/^https:\/\/(x\|twitter)\.com\/[A-Za-z0-9_]+\/status\/\d+/` |
| `reddit-post-clipper.json` | A Reddit thread — discussion consensus, full post and comments | `https://www.reddit.com` |

Import only the ones you need. `default-clipper.json` is the safety net: it has an empty
trigger list, so it catches everything the other four do not.

## Read this first: Interpreter is required

**Every template in this package needs Web Clipper's Interpreter turned on.** Without it,
the templates do not work — they do not fail loudly, they just produce half a note.

Interpreter is the feature that sends the prompt to a language model and writes the answer
into the note. In practice it fills every section listed below — the ones with 🤖 or ⏱️ in
their heading, and the analysis sections in the other templates:

| Template | Sections that need Interpreter |
|---|---|
| YouTube (desktop) | `## Summary 🤖`, `## Key Points ⏱️`, `## Description` |
| YouTube (iOS) | `## Summary 🤖` |
| Default | `## Summary`, `## Key Points`, `## Key Terms` |
| X (Twitter) Post | `## Nature of the Statement`, `## Key Points`, `## What Needs Verification` |

### Set it up

1. Web Clipper → **Settings** → **Interpreter**.
2. Add your provider and its API key.
3. Pick a model from the dropdown.
4. Clip one page and check that the AI sections actually contain text.

### Use `glm-5.3-flash`

**These templates were built and verified against `glm-5.3-flash`.** That is the model used
for every test behind this package — every timestamp check, every "does it invent steps?"
check, every "does it leak the comments?" check.

Other models were tried and produced noticeably worse notes. The failure modes were not
crashes; they were quiet mistakes:

| What went wrong on other models | Why it matters |
|---|---|
| Summary pulled from viewer comments and the sidebar instead of the description | The note then contains claims the creator never made |
| Invented steps, numbers, or tool names that are not on the page | Looks authoritative and is wrong — the worst outcome for a reference note |
| Ignored the "write exactly three lines" instruction in the X template | The section becomes free-form prose and stops being scannable |
| Timestamps off, or reused from a different part of the video | Every link lands in the wrong place |
| `#tag` filter rules ignored, so raw `#hashtags` survived into the note | Your tag pane fills with other people's hashtags |

So: if you use a different model, expect to check the output. The prompts are written
defensively — they say *"use ONLY information on the page"*, *"do not invent numbers"*,
*"do not conclude hoax or fact"* — but a weaker model simply ignores those instructions.
`glm-5.3-flash` follows them.

> [!warning] Without Interpreter, the note still clips — and looks fine
> The properties, the video embed, the timestamp block, and `## Full Content` all fill in
> normally. Only the AI sections stay **empty**, with no error and no warning. It is very
> easy to blame the template for a missing summary when the real cause is a switched-off
> Interpreter. Check that first.

> [!tip] Interpreter costs tokens
> Each prompt is one model call. The Default template makes three, the X template makes
> three, the desktop YouTube template makes three. On a long page that adds up. Delete a
> prompt section you do not need if you want it cheaper.

## Why YouTube needs two templates

| | Desktop | iOS |
|---|---|---|
| Where Clipper runs | Browser extension (Chrome, Firefox, Edge, Safari) | **Safari extension only** |
| Page you are on | `www.youtube.com` | `m.youtube.com` (mobile site) |
| Caption track readable by Clipper | **yes** — `{{transcript}}` works | **no** — the extractor cannot reach it |
| Obsidian community plugins | **Media Extended + Media Notes + YTranscript** — the template was built with them | none needed; YTranscript optional |
| Inline video player | via **Media Extended** | via Obsidian itself, no plugin |
| Clickable timestamps | yes, `youtu.be/ID?t=SECONDS` | **no** |
| Automatic transcript | yes, folded | **no** |

Two separate facts force this split:

1. **iOS has no plugin support at clip time.** On iOS, Clipper is a Safari extension. It can
   read the page and hand markdown to Obsidian, and that is all. Anything that needs a
   community plugin to *become* a video or a working timestamp is out of reach.
2. **Safari gets the mobile site.** `m.youtube.com` is a reduced page. It has no caption
   track for the extractor, and it does not offer the same seeking behaviour as the desktop
   player. So the iOS note is automatically less complete than the desktop note. Do not
   expect them to look the same — they are not meant to.

What that means in practice: **clip on desktop when you want timestamps and a transcript.
Clip on iPhone when you just want the video, the description, and a summary.**

## What a clipped note looks like

**Desktop** — video, summary, timestamped key points, description, folded transcript:

```
---
created: 2026-11-01
tags:
  - "Youtube"
source: https://youtu.be/VIDEO_ID
channel: Channel Name
---

> **Source:** [Channel Name](https://youtu.be/VIDEO_ID)
> **Clipped on:** 2026-11-01T22:26:55+07:00

## Video
![Video|640x360](https://www.youtube.com/watch?v=VIDEO_ID#t=0)

## Summary 🤖
One paragraph, plus a few bullets, drawn only from the page description.

## Key Points ⏱️
- [0:41](https://youtu.be/VIDEO_ID?t=41) — One sentence per key moment.
- [2:03](https://youtu.be/VIDEO_ID?t=123) — Every timestamp is a working link.

## Description
Creator's description, structure and links preserved.

## Transcript (reference)
> [!quote]- Original transcript (auto-caption) - expand only to verify
> **0:01** · Raw caption text, one block per minute.
```

**iOS** — same idea, but the player is a bare embed, and there is no timestamp list and no
transcript:

```
---
created: 2026-11-12
tags:
  - "Youtube"
source: "https://www.youtube.com/watch?v=VIDEO_ID"
channel: "Channel Name"
---

> **Source:** [Channel Name](https://www.youtube.com/watch?v=VIDEO_ID)
> **Clipped on:** 2026-11-12T02:13:09+07:00

---

## Video

![](https://www.youtube.com/watch?v=VIDEO_ID)

[If the player does not appear, open it on YouTube](https://www.youtube.com/watch?v=VIDEO_ID)

---

## Summary 🤖

### Prerequisites
- Node.js/npm
- A GitHub account

### Core steps
1. Run `npm install -g some-cli`
2. Sign in with GitHub

### Tips & troubleshooting
- Availability of the free tier is temporary
```

The iOS player is a plain markdown image whose URL points at the video:

```markdown
![](https://www.youtube.com/watch?v=VIDEO_ID)
```

Obsidian itself recognises that and renders a real player. **No plugin is involved.** That
is the whole trick, and it is why the iOS template works on a phone with nothing installed.

## Default — any web page

A general-purpose template. No video logic, no timestamps, no transcript — just a clean
readable note with the page's own content preserved underneath.

```
---
created: 2026-11-12
tags:
  - "clippings"
source: https://example.com/article
author: Jane Doe
title: How something works
description: A one-line description from the page.
---

> [!info] Source
> [example.com](https://example.com/article)
> Clipped: 2026-11-12

---

## Summary
Two paragraphs, 8-12 sentences, drawn only from the page.

---

## Key Points
- The 6-10 most important points, in page order.
- One compact sentence each.

---

## Key Terms
- **Term** — One sentence explaining it.

---

## Full Content
The page itself, with images isolated on their own lines.
```

Three prompts, three sections, one model call each. The `## Full Content` section is the
raw page, cleaned up by three filters:

| Filter | What it does | Why |
|---|---|---|
| Strip `data:image` | Deletes inline base64 images | They are hundreds of kilobytes of unreadable text and they bloat the note |
| Isolate images | Puts blank lines around every `![alt](url)`, including link-wrapped `[![alt](url)](link)` | Obsidian will not render an image glued to the previous sentence |
| Backtick tags | Wraps `#word` as `` `#word` `` | Otherwise Obsidian turns every `#word` into a tag, and your tag pane fills with noise from other people's pages |

The backtick trick is not cosmetic. Escaping as `\#` does not survive Clipper's filter
pipeline — the backslash is consumed and the tag still forms. Backticks are the only thing
that reliably stops it, because Obsidian formats nothing inside backticks.

> [!note] These filters deliberately avoid `|`
> The image-isolation regex matches a plain image and a link-wrapped image in one pattern,
> using optional groups instead of alternation. See the `|` warning further down.

## X (Twitter) Post

Clips a single post, not a whole thread. Comments and replies are never read — the template
uses `{{meta:property:og:description}}` rather than `{{content}}`, so the model only sees
the post itself.

Two branches, chosen by one condition:

| Condition | Section you get |
|---|---|
| `og:image` contains `amplify_video_thumb` (the post has a video) | `## Video` + `## Video Source` |
| anything else (photo or text only) | `## Status` |

The embedded post is a plain iframe pointing at X's own embed endpoint:

```html
<iframe src="https://platform.twitter.com/embed/Tweet.html?id=POST_ID"
  width="100%" height="550" frameborder="0" allowfullscreen></iframe>
```

No `widgets.js`, no script tag, no plugin. It works in reading view on desktop and iOS.

Three AI sections follow, and they are written to be honest rather than confident:

| Section | What it does |
|---|---|
| `## Nature of the Statement` | Exactly three lines: **Type** (event claim, opinion, complaint, sarcasm, promotion, or a mix), **Markers** (short quotes from the post), **Limits** (what cannot be judged from text alone) |
| `## Key Points` | 3-5 short points. If the post is sarcasm, it says what the author *says*, not what *happened* |
| `## What Needs Verification` | **Check** — what the post leaves out; **How to check** — kinds of sources, never a made-up website name |

The prompts explicitly forbid concluding "hoax" or "fact", and forbid inventing search
results — the model has no internet access. A truncated post (X cuts the preview with `…`)
triggers a warning callout, so you know the analysis is based on a fragment.

## Reddit Post

Clips one thread: the post and every comment under it, then an AI read of what the community
actually concluded.

```
---
title: "Obsidian Plugin Stats | Weekly Plugin Updates (Oct 18 to Oct 24, 2026)"
created: 2026-10-28
url: https://www.reddit.com/r/ObsidianMD/comments/1xfxqp2/...
tags:
  - "source/reddit"
published: 2026-10-26
subreddit: "r/ObsidianMD"
---

> [!info] Source
> [r/ObsidianMD](https://www.reddit.com/r/ObsidianMD/comments/1xfxqp2/...) on Reddit
> Posted by u/ganesshkumar
> Clipped: 2026-10-28

---

## Discussion Consensus 🤖

### Thread Summary
What OP asked or shared, in 2-3 sentences.

### Solutions & Comment Highlights
- The 3-5 most upvoted answers, one sentence each, username named.

---

## Post Content

The post body, then `## Comments` with the full thread — nested replies kept as blockquotes,
each with author, date, points, and a permalink.
```

The AI section is the point of this template. A Reddit thread is usually one question plus
forty opinions, and reading it takes ten minutes; `## Discussion Consensus` gives you the
answer and who gave it.

The prompt is deliberately narrow:

| Instruction | Why |
|---|---|
| Use **only** the thread and its comments | Otherwise the model pads with general advice nobody in the thread gave |
| Name the username | An unattributed claim is useless — you cannot judge who said it |
| Do not invent quotes, upvote counts, or usernames | Upvote numbers look precise and are the easiest thing to hallucinate |
| Do not conclude what the thread does not discuss | A thread of "I don't know" answers should say so |

### You must be signed in to Reddit

Reddit gives a signed-out visitor a stripped page: a login prompt, an interstitial, or a
cut-down feed. `shreddit-post` is not on it, so every selector returns nothing.

The failure is quiet and looks like a broken template:

| Property | Signed out |
|---|---|
| `title` | empty — the note is saved as **Untitled** |
| `subreddit` | empty — the Source line loses the subreddit |
| `published` | empty — the date property stays blank |
| `{{content}}` | the post body, but no comment tree |

Sign in to Reddit once, **in the same browser you clip from**, and keep the session alive.
That session is what makes Reddit serve the real thread. On iPhone this means signing in
inside Safari — not in the Reddit app — because the Web Clipper runs as a Safari extension.

There is no workaround. An unauthenticated request is answered with a JavaScript challenge
page instead of the thread, so there is nothing to extract without a session.

### It only works on new Reddit

The template reads `shreddit-post`, the custom element that the current `www.reddit.com`
interface uses. Three attributes come from it:

| Selector | Gives you |
|---|---|
| `shreddit-post?post-title` | The post title, also used for the filename |
| `shreddit-post?subreddit-prefixed-name` | `r/ObsidianMD`, prefix included |
| `shreddit-post?created-timestamp` | When the post was made |

That means **`old.reddit.com` will not work** — it has no `shreddit-post` element, so the
title, subreddit and date all come out empty. The trigger is `https://www.reddit.com` only,
on purpose.

### `{{content}}` already contains the comments

This is the one thing worth knowing before you edit the template. Defuddle extracts the
comment tree along with the post, so `{{content}}` gives you the post **and** a `## Comments`
section with nested replies — author, date, points, permalink, and `>` blockquotes for depth.

Do not add a second `## Comments` section with your own selector. You would get the thread
twice.

### Dates

Both date properties are `YYYY-MM-DD` with type **Date**, so Obsidian sorts and filters them
properly. `created` is when you clipped it; `published` is when the post was made.

A common mistake is formatting a Date property as `DD-MM-YYYY` or appending a time. A Date
property accepts only `2026-10-28` or `2026-10-28T14:04:19`. Anything else is silently stored
as plain text — it looks right in the note and quietly stops working in Bases and search.

## Plugins

### Desktop — built around three plugins

**The desktop template was made with Media Extended, Media Notes and YTranscript installed.**
That is not decoration: the template's output is designed to be finished by those three. This
is only so that the clipped note works *completely* inside your own Obsidian — the markdown
itself is plain and portable, but the video playback and the transcript only come alive with
the plugins.

| Plugin | Version tested | Role in the clipped note | Without it |
|---|---|---|---|
| **Media Extended** | 4.2.9 | Turns `![Video\|640x360](https://www.youtube.com/watch?v=ID#t=0)` into a real player instead of a broken image, and seeks to the second when you click a `youtu.be/ID?t=…` link | Grey box, and `MediaImage src can only be of http/https/data/blob scheme` in the console; timestamps open a browser tab instead of jumping |
| **Media Notes** | 1.3.0 | Adds media controls and timestamp capture while you take notes over the video — the note becomes a workspace, not just an archive | The note is readable, but you cannot play, pause, or stamp a moment without leaving it |
| **YTranscript** | 1.5.0 | Fetches the transcript on demand. The desktop template already gets `{{transcript}}` automatically, so this is your fallback and your re-fetch tool | Nothing breaks at clip time; you just lose the ability to pull a transcript again later, or for a video whose captions the extractor missed |

Setup: install → enable → open the note. Nothing else needed.

All three are community plugins, so they only affect how the note *renders*. If you skip
them, the clipped markdown is still valid — you simply get less than the template was
designed for.

> [!note] Two of them are desktop-only, one is not
> **Media Extended** and **Media Notes** are both marked `isDesktopOnly: true`, so they do
> not exist on iPhone. That is the main reason the iOS template has to be different.
> **YTranscript** is *not* desktop-only — it works on iOS too, which is why it is listed as
> an option there. What it cannot do is run inside the Safari extension at clip time.

If the player shows **Error 153**, that is YouTube refusing the embed, not a plugin fault —
see the oEmbed check below.

> [!warning] Do not stack video players
> Media Extended plus a second YouTube player plugin on the same note is the usual cause of
> blank players and `Cannot read properties of null` errors. Pick one player and let the
> others handle notes, search, and links.

### iOS — no plugin required

| Plugin | Use |
|---|---|
| *none* | The player comes from Obsidian's own markdown renderer. Nothing to install. |
| **YTranscript** | Optional, and it does work on iOS. Run it manually inside Obsidian when you want a transcript — the Safari extension cannot fetch captions, so nothing is filled in at clip time. |

> [!warning] Do not build an iOS template around YouTube Iframe Timestamps
> Its description says it embeds YouTube videos with timestamps, and it is easy to assume
> `<div id="video-player" class="video-player"></div>` will become a player on its own.
> It will not. In v1.0.0 the plugin only registers a right-click menu item
> (**"Open timestamp on iframe"**) and destroys the player whenever you switch note. An empty
> `<div>` in a clipped note stays empty forever, and on iPhone there is no right-click to
> reach the menu. Use the `![]()` embed instead.

### Optional, but they earn their place

| Plugin | Use |
|---|---|
| **Omnisearch** | Fuzzy full-text search across every transcript at once, with ranked results |
| **Dataview** | Build a video index from the frontmatter (`channel`, `source`, `created`) |
| **Link Embed** | Renders bare links as cards. **Do not** let it take over the `![Video]` embed or it will fight Media Extended |

## Install

1. Download the files you need:
   - `youtube-desktop-clipper.json`
   - `youtube-ios-clipper.json`
   - `default-clipper.json`
   - `x-(twitter)-post-clipper.json`
   - `reddit-post-clipper.json`
2. Web Clipper → **Settings** → **Templates** → **Import** → pick the file.
3. Adjust `path` to the folder where you want notes to land. Defaults:
   `Clippings/Youtube`, `Clippings/Default`, `Clippings/Social`, `Clippings/Reddit`.
4. Enable Interpreter and choose **`glm-5.3-flash`** as the model. Do not skip this — without
   it the AI sections stay empty and the templates look broken.
5. On desktop only: install **Media Extended**, **Media Notes** and **YTranscript**. The
   desktop template was built with those three — the markdown works without them, but the
   player, the media controls and the transcript do not.
6. Open a page and click the Clipper icon.

Every template ships in two forms. They hold the same JSON:

| File | What to do with it |
|---|---|
| `youtube-desktop-clipper.json`, `default-clipper.json`, … | **Import this one.** Web Clipper → Settings → Templates → Import |
| `Desktop Template Code.md`, `Default Template Code.md`, … | Read it on GitHub, or copy the code block by hand |

Use the `.json` files. The `Code.md` pages exist so you can see exactly what a template does
before you install it, without downloading anything.

The YouTube files are triggered by different domains, so they never fight:

| Template | Trigger |
|---|---|
| Desktop | `https://www.youtube.com/watch` |
| iOS | `https://m.youtube.com/watch`, `/shorts/`, `/live/` |

If your iPhone loads the desktop site, pick the iOS template manually from the dropdown.

> [!tip] Keep the iOS triggers broad
> Clipper matches a plain trigger string with `url.startsWith(...)`, and when nothing matches
> it silently falls back to **the first template in your list**. A trigger of only
> `https://m.youtube.com/watch` misses `/shorts/` and `/live/`, so those clips quietly become
> notes built with the wrong template. List all three.

> [!warning] Put `default-clipper.json` last in the list
> It has an empty trigger list, which makes it the fallback for every unmatched page. That is
> what you want — but it also means that if a YouTube or X clip fails to match, it is this
> template that quietly produces the note, and you will not see an error.

## How it works (and what breaks)

- **`|` inside a `replace` pattern is fatal.** Clipper splits the filter chain on `|`
  *without* looking at quotes:
  ```javascript
  const [variablePath, ...filterParts] = variableString.split('|').map(part => part.trim());
  ```
  So this silently does nothing, because the regex alternation `|` is treated as a filter
  separator:
  ```
  {{url|replace:"/.*(?:v=|youtu\.be\/|shorts\/)([\w-]{11}).*/":"$1"}}
  ```
  The `replace` never runs, `{{url}}` is emitted unchanged, and the note gets a URL glued
  into another URL. Keep regex patterns free of `|`, or avoid regex entirely.
- **`og:url` is the cleanest way to get the video ID on iOS.** No regex needed. YouTube
  normalises every address shape into one clean URL:
  ```html
  <meta property="og:url" content="https://www.youtube.com/watch?v=VIDEO_ID">
  ```
  Verified for `m.youtube.com/watch?v=…&pp=…`, `m.youtube.com/shorts/…`,
  `m.youtube.com/live/…` and `youtu.be/…` — all of them come out as the same tidy URL,
  without tracking parameters. Use `{{meta:property:og:url}}` directly.
- **Do not hand-write a YouTube `<iframe>` for iOS.** Inside a mobile WebView the request
  carries no `Referer`, and YouTube answers with **Error 153 — "Video player configuration
  error"**. Adding `referrerpolicy="strict-origin-when-cross-origin"` makes it worse: it
  strips the very header YouTube needs. The `![]()` embed avoids this because Obsidian
  builds the frame itself.
- **`{{transcript}}` is real, on desktop.** The Clipper's extractor adds it for YouTube
  pages, pulled from the caption track, so the template does not need to open the
  transcript panel. It does **not** work in the Safari extension, which is why the iOS
  template leaves it out.
- **`context` is what makes timestamps work.** The default prompt context is the page HTML
  with `href`/`src` stripped, so the model never sees the video URL. The desktop template
  sends its own `context` containing `VIDEO_ID` and the transcript, which is why it can
  build `youtu.be/ID?t=SECONDS` links.
- **Seconds are computed by the model** (`minutes × 60 + seconds`). Spot-check two or three
  lines after clipping; off-by-one is normal, invented timestamps are not.
- **Transcript language follows the video's default caption track**, not your UI language.
- **Some videos cannot be embedded** (owner disabled it). Check with
  `https://www.youtube.com/oembed?url=<video-url>&format=json` — a 401 means no inline
  player, ever. The note still works; only the player is missing. On iOS this is the one
  remaining reason a player stays blank.
- **Date properties accept only two formats:** `2026-11-01` (Date) and
  `2026-11-01T22:26:55` (Date & time). Anything else — including `2026-11-01 22:26` — is
  written as plain text and stops sorting and filtering as a date.
- **Three prompts = three model calls** per clip on desktop. On long videos this costs
  tokens; delete the `## Key Points` prompt if you want it cheaper.

## Everything is in English

All prompts, headings and properties across all five templates are English. Nothing is
translated, so a note reads the same as the page and quoted content is copied verbatim.

To switch to another language, edit the prompts and the headings in the template you care
about and leave the rest alone:

| Template | Headings to rename |
|---|---|
| YouTube desktop | `## Summary`, `## Key Points`, `## Description`, `## Transcript (reference)` |
| YouTube iOS | `## Summary` |
| Default | `## Summary`, `## Key Points`, `## Key Terms`, `## Full Content` |
| X (Twitter) Post | `## Video` / `## Status`, `## Video Source`, `## Initial Information`, `## Nature of the Statement`, `## Key Points`, `## What Needs Verification` |
| Reddit Post | `## Discussion Consensus`, `## Post Content` |

Each prompt begins with an instruction like `write a summary in plain, compact English` —
change that phrase in the prompt text too, or the model will answer in English regardless.

Do **not** try to inject a variable into a prompt — `{{"..."}}` is passed to the model as
literal text, so `{{language}}` inside a prompt would reach the model unrendered. Only the
`context` field is rendered.

> [!note] Dates in this package are ISO
> Properties use `YYYY-MM-DD`, and the date shown in the note body is `YYYY-MM-DD` as well.
> That is unambiguous for an international audience: `03-04-2026` means March 4th to some
> readers and April 3rd to others. Change the body format to `DD-MM-YYYY` in the template if
> your readers expect that — but leave the **property** as `YYYY-MM-DD`, because a Date
> property accepts only that form.
